# 背景图

**背景图由用户提供。** 大多数编码智能体没有生图能力，不要假设自己能画一张出来。先问用户要，拿到再往下走。

IDE 背景图和普通壁纸的要求不一样：壁纸追求画面饱满，IDE 背景图要主动让位给代码。所以用户随手给的图不一定能直接用，下面是判断和补救的办法。

## 拿到图先看三件事

### 1. 主体在哪

最理想是主体（人物 / 建筑 / 焦点）在**画面右侧 25%–35%**，因为右侧通常是 AI 面板或空白编辑区，左侧要留给文件树和代码。

- 主体在右 → 直接用。
- 主体在左 → `prepare-background.sh --flip` 水平镜像翻过去。人物、风景一般翻了看不出来；有文字、招牌、不对称 Logo 的图翻了会露馅。
- 主体在正中间 → 镜像救不了，会一直被代码盖住。建议换图，或者接受"主体基本看不见、只留色调氛围"的效果。

### 2. 亮度够不够暗

运行时还会在图上叠一层渐变和半透明面板。原图偏亮的话，最终会灰白发糊、代码看不清。

偏亮的图有两个补救方向：调低 `skin.css` 里 `html` 的渐变透明度让背景更暗，或者调高 `--qoder-skin-editor` 的不透明度让面板更实——后者更稳，代价是背景更看不见。

### 3. 细节密不密

密集纹理、高对比条纹、大面积文字和 UI 截图都不适合当背景，字盖上去会糊成一团。低细节、大块暗部的图最好用。

## 处理

```bash
./scripts/prepare-background.sh <slug> <图片路径> [--flip] [--width 1672] [--quality 82]
```

脚本做四件事：

1. 统一格式（png / jpg / heic / tiff / webp 都能读）
2. 可选水平镜像
3. 缩放到目标宽度（默认 1672，比原图小才缩，不放大）
4. 压成 WebP 存进 `skins/<slug>/assets/`，原图另存一份 PNG 备二次编辑

**元数据会在转换中丢掉**，包括手机照片里的 GPS 坐标和拍摄设备信息。用户自己的照片当背景时这一步很重要。

没有 `cwebp` 时自动退回 PNG，并同步改写 `skin.json` 里的 `background` 路径——注入器同样支持 PNG，只是体积大不少（背景图会整段 base64 编进 CSS 变量注入）。

比例偏离 16:9 太多时脚本会提示，因为铺满窗口用的是 `cover`，比例差得多就会裁掉不少内容。

## 如果你的智能体能生图

这是可选加速路径，不是默认路径。生成前把构图要求告诉用户并确认：

- 原创角色 / 场景，**不要指名现成动漫 IP、真实人物、品牌 Logo**
- 主体位于画面右侧，左侧留大面积低对比暗部
- 无文字、无水印、无界面元素
- 明确色调关键词，和主题配色对齐（accent 色最好在图里出现）
- 16:9，整体亮度压低

内置示例月夜樱的构图：原创成年女性角色、月夜赛博樱花工作室、人物在右、左侧低对比代码区、无文字无品牌。

## 和配色联调

背景图和主题配色是一起看的：

- 图定下来后，从图里取一个颜色当 accent，整体会更协调。
- 图偏冷就别配暖色 accent，反之亦然。
- 最后一定在实机上看，而不是只看图片本身——叠了渐变、半透明和毛玻璃之后，观感和原图差别很大。
